# ExamSathi Question Quality Standard

This is the permanent content and release standard for every exam listed in ExamSathi.

## 1. Exam-specific blueprint first
- Create a separate question bank for each exact exam name. Never fill one exam with another exam's questions.
- Before authoring a bank, record the latest verified exam pattern: stages/papers, subjects, section weights, question count, duration, marks, negative marking, syllabus and difficulty expectations.
- Prefer the recruiting body's latest official notification, syllabus, information bulletin and official answer key. Record the source URL and the date checked.
- If a pattern cannot be verified, label the bank as a provisional practice blueprint and do not claim exact pattern matching.

## 2. Difficulty must match the exam
- Every question should be tagged difficulty: easy, moderate or hard, and include a specific topic.
- Do not make a bank artificially easy to increase question count. Use multi-step calculations, application, conceptual traps, close distractors and exam-level reasoning wherever that exam requires them.
- Difficulty mix and subject quotas must come from the exam's verified pattern and representative papers, not one universal percentage for every exam.
- For advanced exams (for example UPSC, SSC CGL, banking officer, JEE, NEET, GATE and UGC NET), retain the appropriate depth and complexity. For eligibility/recruitment exams, follow their own syllabus and level rather than copying SSC-style questions.

## 3. Set generation rules
- The interface offers 20 numbered sets for each selected length: 10, 50 and 100 questions.
- A set is playable only when its selected exam, subject and year filters contain enough distinct questions for that length.
- No duplicate question is allowed inside a single set. Reuse across different sets is permitted only when the bank does not yet contain 2,000 distinct questions for twenty 100-question sets; the overlap must be disclosed.
- Never create duplicate filler questions to make a set appear complete. Show the actual available count and keep insufficient sets locked.
- Subject distribution inside a set must follow that exam's verified blueprint. Do not build a 100-question combined paper by blindly taking a random slice of the entire bank.

## 4. Question and answer quality
Every question must include:
- Hindi and English wording where the exam supports bilingual practice; both versions must preserve the same meaning.
- Four plausible answer options, one unambiguous correct answer, and a zero-based answer index.
- A clear Hindi/English explanation, including the method or reasoning for numerical and analytical questions.
- subject, topic, and difficulty metadata.
- provenance.kind, stable provenance.questionId, source title/URL where applicable, answer-key review status and reuse status.

## 5. PYQ honesty and review
- Keep official previous-year questions separate from original/authored practice questions.
- A question is a PYQ only when its exam, year, paper/shift and source have been verified. Otherwise label it original practice/model practice.
- Verify every answer against a reliable official key or an independently reviewed solution before publishing.
- Flag disputed, outdated or ambiguous questions for review; do not silently publish them as confirmed facts.

## 6. Release gate
A bank is ready for publication only after:
1. Exam blueprint and source references are reviewed.
2. Duplicate and malformed-question checks pass.
3. Answer indexes, options and explanations pass validation.
4. Subject balance and difficulty are checked against the blueprint.
5. The number of playable sets matches the number of complete sets actually supported by distinct questions.

A catalogue entry is not proof that its question bank exists. Until a dedicated bank is populated and reviewed, that exam remains unavailable for mock tests.
